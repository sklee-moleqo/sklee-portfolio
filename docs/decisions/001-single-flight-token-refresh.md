# 001. 토큰 재발급을 single-flight로

- 상태: 채택

## 배경

개발 초기, 토큰 만료 직후 대시보드를 열면 간헐적으로 로그인 화면으로 튕기는 문제가 있었습니다.
원인은 동시에 돌아온 401마다 재발급 API를 부른 것이었습니다. 서버는 refresh token을 한 번 쓰면
바꾸기 때문에, 두 번째 재발급부터 "이미 사용된 토큰"으로 실패했습니다.

## 결정

- 재발급 Promise를 모듈에 하나만 두고, 진행 중이면 다른 401 요청은 그 결과를 기다립니다.
- 원 요청은 새 토큰으로 한 번만 재시도합니다.
- 로그인·로그아웃마다 세션 세대 값을 올리고, 재발급 시작 때와 세대가 다르면 결과를 버립니다.

## 검토한 대안

- **만료 직전에 미리 재발급(타이머)**: 탭이 백그라운드일 때 타이머가 늦어져 결국 401 처리가 또 필요합니다. 보조 수단으로만 씁니다.
- **요청을 직렬화하는 큐**: 정상 상황에서도 요청이 느려집니다.

## 결과

간헐 로그아웃이 사라졌습니다. 같은 규칙을 미들웨어(서버) 쪽 재발급에도 적용했습니다.
